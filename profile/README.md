## What is Mistic Clouds?

**Mistic Clouds is an independent organisation for building useful things, trying out ideas, and working on projects together.** It is a shared place for applications, experiments, developer tools, and the bits of infrastructure that support them.

The work is not limited to one product or a fixed set of technologies. Some projects begin with a problem worth solving; others start as a small experiment or a question worth exploring. A few may grow into long-running projects, while others may stay small. Both have a place here.

Mistic Clouds is not a company or an agency. It is an independently started space with room for other people to contribute, collaborate, and help shape what comes next.

## Built to be shared

Mistic Clouds is intended to be more than a collection of repositories. It is a place where people can bring ideas, improve existing work, learn from one another, and build something together. Collaboration may look different from project to project: fixing a bug, suggesting an improvement, testing an experiment, writing documentation, or starting something new.

You do not need to be involved in every project. Take a look around, find something that interests you, and start a conversation in the repository where the work lives.

## How to collaborate

- **Start with the project README.** It explains what the repository does, how to run it, and whether the work is ready for contributions.
- **Discuss larger changes first.** Open an issue before spending time on a substantial feature or redesign. It helps avoid duplicated effort and keeps expectations clear.
- **Keep contributions clear.** Focused pull requests, useful descriptions, and updated documentation make it easier for others to review and maintain the work.
- **Respect project-specific guidance.** Some repositories may have their own contribution notes, priorities, or limits. Those take precedence.

Not every repository will be at the same stage. Some will be ready for collaboration; others may still be rough experiments. Their documentation should make that clear.

## Take a look around

The repositories are the best way to see what is happening. Each project has its own context, instructions, and next steps.
